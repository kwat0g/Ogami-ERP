# Analytics and forecast data

`analytics-forecasts` writes manual planning entries for active product/customer portal pairings, plus an all-customer total that equals the sum of those plans. Quantities use stable 50-piece lots and a small December/January seasonal adjustment. Forecast plans are planning inputs, not historical sales.

KPI definitions come from `KpiDefinitionSeeder`; system settings are untouched. `analytics-forecasts` computes snapshots from operational records with `KpiSnapshotService`. The separate `illustrative-kpi-history` layer fills periods that lack a source-computed snapshot from [`fixtures/illustrative-kpi-history.json`](../../api/database/seeders/Demo/fixtures/illustrative-kpi-history.json). It derives each value from the app's active KPI target plus a deterministic monthly offset, applies the app's direction and thresholds, preserves any existing source-computed snapshot, and writes only the derived `kpi_snapshots` aggregate table. Snapshot breakdown metadata identifies these rows as `illustrative_history` and records planted issue notes. No sales, receipt, payroll, inventory, or accounting transaction is fabricated by this layer.

The illustrative fixture covers 18 periods relative to `--as-of`. It includes a late-customer aging increase, an attendance dip, a spending spike, a defect/first-pass-yield/NCR cluster, an inventory-turnover dip, a machine downtime cluster, supplier-quality and delivery delays, and work-order completion pressure. These values make trend charts and KPI status badges useful during a visual walkthrough; they are synthetic and must not be presented as reconciled operational results.

The `forecast-accuracy-history` layer adds a confirmed October order for 500 units of the already catalogued Product 6 / Customer 1 pair. It uses the existing November agreement's price and tier schedule to create a non-overlapping, October-only agreement through `PriceAgreementService`, then creates and confirms the order through `SalesOrderService`. It creates both customer-scoped and all-customer October forecasts of 550 through `ForecastingService::storeManual()` and reconciles them from the order through `ForecastingService::reconcileActuals()`. The measured outcome is 500 actual, −50 variance, 10% MAPE, and one evaluated period. The backward extension of the current agreement schedule is an explicit demo assumption; it is not an independently verified October customer price. The layer is guarded, deterministic, and idempotent, and writes no invoice, delivery, collection, or production record.

The dataset now has one forecast period reconciled to sales, but it still lacks a 10-month source-backed supplier-quality history and a 10-order production-to-cash history. The `demo:verify --analytics` command reports those remaining gaps. It also confirms all 11 KPI trends have at least ten measured points after the illustrative layer runs.

Run the forecast layer with `php artisan demo:seed --only=analytics-forecasts --as-of=YYYY-MM-DD`, then seed trend-only chart history with `php artisan demo:seed --only=illustrative-kpi-history --as-of=YYYY-MM-DD`. The illustrative layer is deterministic and idempotent for a fixed as-of date and fixture version.
