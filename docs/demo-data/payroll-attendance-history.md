# 2026 Payroll Attendance History

`payroll-attendance-history` adds a compact service-backed attendance history for the payroll demo. It takes the first 25, 80, or 100 active employees for `small`, `demo`, or `full` scale and writes one shift-aware attendance day per completed month in 2026. September is skipped because its payroll periods are already approved and attendance is locked by the application.

The deterministic distribution includes present days, lateness, undertime, absences, and overtime. Punches are calculated against each employee's effective shift and the app's holiday calendar, then saved with `AttendanceService`. Overtime requests detected by the app are approved by an eligible user through `OvertimeService`, with historical decision timestamps. Notifications are suppressed; broadcasts use the local log transport when the layer runs in the live demo container.

This layer also creates one pending company-loan request with an October 26, 2026 application timestamp through `LoanService`, using the app's configured principal limit and approval workflow. It remains pending because final approval would post to the closed October accounting period. This layer does not compute or modify payslips. The first uncapped run was stopped after it had committed some attendance rows, so the current database contains attendance for 105 employees rather than only the capped 80-person cohort. October's existing draft periods remain the available period for a live computation. The active company loan currently starts in November; the app has an existing issue where that loan was deducted before its start date, documented as F-058. Do not treat September's existing payslips as a clean loan-deduction example.
